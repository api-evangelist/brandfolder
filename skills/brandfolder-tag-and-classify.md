# Tag and classify Brandfolder assets

Base URL `https://brandfolder.com/api/v4`, `Authorization: Bearer {BF_API_KEY}`.

Brandfolder has three distinct classification systems and they are not
interchangeable. Pick deliberately.

| System | Shape | Use it for |
|---|---|---|
| **Tags** | Free-form strings on an asset | Keywords, search recall. Can be auto-generated by Brandfolder's AI (`attributes.auto_generated`, `attributes.source`). |
| **Custom fields** | Typed key → value, key defined at Brandfolder level | Structured metadata you will filter or report on. Keys can be `required`, `restricted`, `prioritized`, and carry `allowed_values`. |
| **Labels** | A tree scoped to a Brandfolder (`path`, `depth`) | Hierarchical organization, e.g. campaign > region > channel. |

## Tags

- Read the vocabulary already in use before inventing terms:
  `opIdApiV4BrandfoldersTagsByBrandfolderIdGet` →
  `GET /brandfolders/{brandfolder_id}/tags`.
- Read an asset's tags: `opIdApiV4AssetsTagsByAssetIdGet` →
  `GET /assets/{asset_id}/tags`.
- Add tags to an asset: `opIdApiV4AssetsTagsByAssetIdPost` →
  `POST /assets/{asset_id}/tags`.
- Rename a tag account-wide: `opIdApiV4TagsByIdPut` → `PUT /tags/{tag_id}`.
- Remove tags from an asset: `opIdApiV4AsyncTagsAssetsByAssetKeyDelete` →
  `DELETE /async/tags/assets/{asset_key}`. Note the `async` in the path — this
  one is queued, so a subsequent read may still show the tag. Poll
  `GET /assets/{asset_id}/tags` rather than assuming immediate consistency.

Check `attributes.auto_generated` before editing. Overwriting an AI-generated
tag set with your own is a real decision, not a cleanup.

## Custom fields

1. List the keys that exist:
   `opIdApiV4BrandfoldersCustomFieldKeysByBrandfolderIdGet` →
   `GET /brandfolders/{brandfolder_id}/custom_field_keys`.
   Inspect `allowed_values` — if a key is `restricted`, a value outside that
   list will be rejected.
2. Create a key only if it genuinely does not exist:
   `opIdApiV4BrandfoldersCustomFieldKeysByBrandfolderIdPost` →
   `POST /brandfolders/{brandfolder_id}/custom_field_keys`.
   Key sprawl is the standard failure mode here — near-duplicate keys
   ("Campaign", "campaign", "Campaign Name") are invisible to search and
   permanent in reporting.
3. Set a value on an asset:
   `opIdApiV4CustomFieldKeysCustomFieldValuesByCustomFieldKeyIdPost` →
   `POST /custom_field_keys/{custom_field_key_id}/custom_field_values`.
   The operation hangs off the **key**, not the asset — the asset is named in
   the body.
4. Read an asset's values: `opIdApiV4AssetsCustomFieldValuesByAssetIdGet` →
   `GET /assets/{asset_id}/custom_field_values`.
5. Update one: `opIdApiV4CustomFieldValuesByIdPut` →
   `PUT /custom_field_values/{custom_field_value_id}`.

## Labels

- List: `opIdApiV4OrganizationsLabelsByBrandfolderIdGet` →
  `GET /brandfolders/{brandfolder_id}/labels`. Each label carries `path`,
  `depth` and `position` — that is the tree.
- Re-parent: `opIdApiV4MoveLabelPut` → `PUT /labels/{label_id}/move`.
- Assets under a label: `opIdApiV4LabelsAssetsByLabelIdGet` →
  `GET /labels/{label_id}/assets`.

## Retry safety

No idempotency key exists. Re-posting a tag or a custom field value is a second
write, not a no-op. Before any retry, read the current state
(`GET /assets/{asset_id}/tags`, `GET /assets/{asset_id}/custom_field_values`)
and reconcile. This matters most in bulk classification jobs, which is exactly
where retries happen.

## Errors

- `400` — a required custom field attribute is missing, or a value violates
  `allowed_values` on a `restricted` key.
- `403` — the key's user cannot write to this Brandfolder.
- `404` — wrong `custom_field_key_id` / `asset_id` / `label_id`.
- `429` — back off; there is no `Retry-After`.
